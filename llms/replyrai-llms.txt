# Replyr.ai

> Replyr.ai (Replyr Sdn Bhd, Kuala Lumpur, Malaysia) is an AI customer-engagement
> and patient-acquisition platform for clinics. It runs GPT-style chat assistants
> that reply across WhatsApp, Instagram, Facebook Messenger and other chat
> channels to qualify leads, answer questions, recommend products and book
> appointments, packaged with Meta/Google ad campaigns and the BookAClinic
> discovery marketplace. The operator console at app.replyr.ai exposes a REST API
> of 65 operations, documented with Swagger UI and a Swagger 2.0 specification.

Generated by API Evangelist on 2026-08-13. Replyr does not publish an llms.txt of
its own (https://replyr.ai/llms.txt returns 404), so this file is generated from
the provider's published Swagger 2.0 document and from live probes. It is a
third-party description, not a Replyr publication.

## API basics

- Base URL: https://app.replyr.ai/api
- Reference: https://app.replyr.ai/api (Swagger UI 3.16.0)
- Specification: Swagger 2.0, info.version 1.1, 48 paths, 65 operations, 8 tags
- Authentication: API key in the `X-ACCESS-TOKEN` request header, issued from the
  operator console. Applied globally - every operation requires it. No OAuth, no
  scopes, no bearer tokens.
- Versioning: none. No version segment in the path, no version header.
- Pagination: `offset` / `limit` query parameters on three operations only
  (getPipelines, pipelinesGetCards, pipelinesGetComments). Collections wrap
  results in a top-level `data` array.
- Errors: vendor envelope `{"error":{"code":<int>,"message":<string>}}`, served
  with Content-Type `text/html`. Not RFC 9457. No symbolic error codes.
- Rate limits: none documented, no rate-limit headers observed, no 429 declared.
- Idempotency: not supported. Retrying a messaging or payment write can duplicate
  a real-world side effect.
- Webhooks / events: none published. No AsyncAPI, no callbacks.
- MCP server: Replyr does not ship one. (The API's GET /agents/mcp lists MCP
  connections a *customer* configures for their own AI agents inside Replyr.)

## Data model

Account is the tenant root (`page_id` is the tenant key). Contact is the hub - 21
of 65 operations are addressed by `contact_id`. Entities: Account, Contact, Tag,
Custom_field, Admin, Team, Pipeline, PipelineStage, Opportunity,
OpportunityComment, Agent, Calendar, Appointment, Product, ProductCart, Cart,
Order. Identifiers are bare integers with no type prefix (Order.id and
Cart.order_id are strings).

Appointment is defined in the schema but reachable through no published
operation - there is no endpoint to list, create, reschedule or cancel an
appointment, even though appointment booking is the product's headline use case.
Flows, bot fields, integrations, templates and the AI function/MCP/file lists have
operations but no published schema.

## What Replyr does NOT publish

- No pricing tiers. The homepage #pricing section is a "Qualify My Clinic" lead
  form; https://app.replyr.ai/en/register returns 404. Contact sales only.
- No terms of service or privacy policy at a working URL.
- No status page, SLA, changelog, deprecation policy or versioning policy.
- No SDK or client library in any public registry.
- No CLI, no Postman collection, no sandbox or test credentials.
- No /.well-known/ documents - 16 paths probed across 2 hosts, all 404.
- No A2A agent card, no MCP server, no AsyncAPI, no webhooks.
- No compliance page, trust center or named certification. Notable given the
  healthcare context: the product moves patient enquiries through WhatsApp.
